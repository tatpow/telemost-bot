# Telemost Auto-Join Bot

> ⚠️ **Это вайб-код / MVP.** Проект написан быстро, «на вайбе», как рабочий
> прототип (proof-of-concept), а не готовый к продакшену продукт. Он **делает
> своё дело**, но местами наверняка потребует доработки напильником —
> особенно селекторы кнопок Телемоста, если Яндекс поменяет вёрстку. Относись
> к нему как к «MVP, который потом можно довести до
> ума», а не как к вылизанному сервису. Ниже честно перечислено, что уже
> работает и что скорее всего придётся допилить (см. [Известные
> ограничения](#известные-ограничения)).

Telegram-бот, который по команде админа группы подключается к встрече
Яндекс Телемоста под твоим корпоративным аккаунтом и записывает её
(видео + звук через ffmpeg), пока не поступит `/stop` или встреча не
завершится сама.

Типичный сценарий: у группы есть онлайн-пара в Телемосте, все опаздывают/
не могут — бросаешь боту `/connect <ссылка>`, он заходит и пишет запись,
а по окончании присылает файл (или путь к нему) в чат.

---

## Как это работает

- **Вход в Яндекс — НЕ автологин.** Один раз ты вручную логинишься
  (`python scripts/save_session.py`), скрипт сохраняет **портативную сессию**
  `browser_profile/storage_state.json` (cookies+localStorage в JSON). Дальше бот
  переиспользует её — в том числе в Docker на Linux, даже если логинился на
  Windows. Это надёжнее автологина, не ломается на 2FA/капче и, в отличие от
  самого профиля Chromium, переносится между ОС (см. врезку про «гостя» ниже).
- **Браузер всегда видимый (headed).** Настройки `HEADLESS` больше нет.
  В Docker окно рисуется в виртуальный дисплей **Xvfb**, и именно этот
  дисплей захватывает ffmpeg. (Почему так — см. врезку ниже.)
- **Подключение к звонку.** Playwright открывает ссылку, проходит экран
  «Продолжить в браузере», выключает микрофон и камеру на превью и жмёт
  «Подключиться». Селекторы — вверху `browser_worker.py`.
- **Запись.** Официального «серверного» API записи у Телемоста нет, поэтому
  бот пишет то, что видно/слышно в браузере: экран через `ffmpeg x11grab`
  и звук через виртуальный аудио-синк PulseAudio (без реальной звуковой
  карты — стандартный трюк для headless-серверов).
- **Остановка.** По `/stop` от админа, либо автоматически — когда бот находит
  на странице признак завершения звонка (`END_CALL_MARKERS`: «Организатор
  завершил встречу для всех», модалка «Оцените качество связи» и т.п.) или
  вкладка закрывается.

> 💡 **Почему убрали `HEADLESS` (важно).** В настоящем headless-режиме Chromium
> вообще ничего не рисует в X11. Из-за этого ffmpeg захватывал пустой дисплей —
> получался **чёрный экран с крестиком-курсором и без звука**. Вдобавок Яндекс
> в headless чаще сбрасывал сохранённую сессию, и бот заходил **гостем**.
> В видимом режиме (headed) обе проблемы исчезают. Поэтому теперь браузер
> **всегда** headed, а «серверность» обеспечивает Xvfb в Docker. Отдельного
> переключателя нет специально — он только ломал бота и в проде, и в деве.

## Структура проекта

```
telemost-bot/
├─ bot.py                 # точка входа: команды Telegram (/connect, /stop, /status, /help, /id)
├─ browser_worker.py      # Playwright: открыть Телемост, залогиниться (профилем), нажать «Подключиться»
├─ recorder.py            # обёртка над ffmpeg (x11grab + PulseAudio -> mp4)
├─ config.py              # чтение .env и пути к папкам
├─ utils.py               # единый логгер
├─ scripts/
│  └─ save_session.py     # ОДИН РАЗ: ручной логин в Яндекс -> browser_profile/storage_state.json
├─ Dockerfile             # образ с Chromium + ffmpeg + Xvfb + PulseAudio
├─ docker-compose.yml     # запуск + volume'ы (профиль, записи, скриншоты)
├─ entrypoint.sh          # старт Xvfb/PulseAudio и затем bot.py (внутри контейнера)
├─ requirements.txt       # aiogram, playwright, python-dotenv
├─ .env.example           # шаблон конфигурации (копируется в .env)
│
│  # создаётся автоматически, в git НЕ попадает (см. .gitignore):
├─ .env                   # твой реальный конфиг с BOT_TOKEN  ← СЕКРЕТ
├─ browser_profile/       # профиль Chromium + storage_state.json (ЖИВАЯ сессия Яндекса)  ← СЕКРЕТ
├─ recordings/            # записанные встречи (.mp4)
└─ debug_screenshots/     # скриншоты страниц при проблемах с UI
```

## Безопасность

Проект работает с секретами — **прежде чем куда-то выкладывать, проверь**:

- **`.env`** содержит `BOT_TOKEN` (полный доступ к боту). Он **в `.gitignore`** и
  не коммитится. В репозиторий кладётся только `.env.example` без секретов.
- **`browser_profile/`** — это твоя **залогиненная сессия Яндекса** (по сути,
  ключи от аккаунта). Тоже в `.gitignore`. Никогда не коммить и не пересылай
  эту папку кому попало.
- **`recordings/`** — записи встреч, могут быть приватными. Тоже игнорируются git.
- Если токен **всё же куда-то утёк** (попал в коммит, переслал в чат, и т.п.) —
  перевыпусти его: [@BotFather](https://t.me/BotFather) → `/revoke` → выбрать
  бота → получить новый токен, вписать в `.env`.
- **Запись без согласия.** Предупреди группу/преподавателя, что встречи
  записываются — в зависимости от того, как это принято у вас.

## Установка и запуск

Есть два режима. **Запись работает только в Docker** (нужны Xvfb + PulseAudio,
которых на голом Windows нет). Локальный режим — для отладки логики подключения.

### Шаг 0. Токен и ID чата (нужно в обоих режимах)

1. Создай бота у [@BotFather](https://t.me/BotFather), получи `BOT_TOKEN`.
2. `cp .env.example .env` и впиши `BOT_TOKEN`.
3. Добавь бота в группу и **дай ему права администратора** (иначе он не сможет
   проверять, кто админ, и читать команды в группе).
4. Отправь в группе команду **`/id`** — бот пришлёт `chat_id` (а если группа —
   форум с темами, то и `thread_id`). Впиши `chat_id` в `GROUP_CHAT_ID` в `.env`
   (тогда бот слушает только эту группу; в других группах и в личке — молчит;
   `0` = отвечать в любом чате, для прода не рекомендуется).
5. **(Опционально)** Чтобы бот работал только в одной теме форума — впиши её
   `thread_id` из `/id` в `GROUP_THREAD_ID`. В остальных темах он коротко
   попросит перейти в нужную. `0` = любая тема.

### Вариант A — локально (Windows), режим отладки без записи

Годится, чтобы проверить, что бот логинится и корректно жмёт «Подключиться».
Запись здесь **не пишется** (нет Xvfb/PulseAudio) — поставь `RECORD_ENABLED=false`.

```bash
python -m venv venv
venv\Scripts\activate            # Windows;  на macOS/Linux: source venv/bin/activate

pip install -r requirements.txt
playwright install chromium
```

> 🛠 **Если `pip install -r requirements.txt` падает с ошибкой про
> «Microsoft C++ Build Tools» / компиляцию** — pip пытается собрать зависимости
> из исходников, потому что под твою версию Python нет готовых wheel'ов.
> Любой из вариантов решает проблему:
> 1. поставить те же пакеты без жёстких пинов:
>    `pip install aiogram python-dotenv playwright`
>    (пакет называется `python-dotenv`, импортируется как `dotenv`);
> 2. использовать **Python 3.11 или 3.12** (под них wheel'ы точно есть);
> 3. поставить [Microsoft C++ Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/);
> 4. или просто запускать всё через **Docker** (там сборка уже сделана).

Дальше:

```bash
# в .env: RECORD_ENABLED=false  (на Windows запись всё равно не работает)
python scripts/save_session.py   # откроется окно — залогинься, вернись в терминал и нажми Enter
python bot.py                    # запуск бота; в группе пиши /connect <ссылка>
```

### Вариант B — Docker (прод, с записью)

1. **Сначала получи сохранённую сессию.** Один раз запусти
   `scripts/save_session.py` на своём Windows/Mac (см. Вариант A, шаги
   установки). Залогинься, вернись в терминал и нажми Enter — появится
   `browser_profile/storage_state.json` (портативная сессия). Именно её бот
   использует в контейнере, поэтому логин с Windows работает и в Linux.
2. Заполни `.env`: `BOT_TOKEN`, `GROUP_CHAT_ID`, и `RECORD_ENABLED=true`.
3. Собери и запусти:
   ```bash
   docker compose up --build -d
   docker compose logs -f
   ```
   Папки `browser_profile/`, `recordings/` и `debug_screenshots/` смонтированы
   как volume — сессия и записи переживут пересборку контейнера.

> 🧩 **Про вход «гостем» (важно).** Раньше бот в Docker заходил гостем, даже
> когда `browser_profile/` был на месте. Причина: **cookies внутри профиля
> Chromium шифруются ключом операционной системы** (Windows — DPAPI, Linux —
> keyring/фолбэк), поэтому профиль, залогиненный на Windows, в Linux-контейнере
> не расшифровывается — куки молча отбрасываются, и остаётся гость.
>
> Теперь это решено: `save_session.py` сохраняет **портативный
> `storage_state.json`** (куки+localStorage в обычном JSON, без шифрования ОС),
> а бот при старте использует именно его (в логах — `Использую портативную
> сессию: ...`). JSON переносится между ОС, поэтому логин с Windows работает
> в Docker на Linux.
>
> Если всё же видишь гостя — смотри логи:
> - `storage_state.json не найден ... откатываюсь на постоянный профиль` —
>   файла нет в смонтированном `browser_profile/`. Перезапусти шаг 1 и убедись,
>   что в конце появилась строка `[OK] Портативная сессия сохранена`.
> - `Нет ни ... сессии Яндекса ещё нет` — сессия вообще не создавалась,
>   выполни шаг 1.

## Команды бота

Только для **админов группы**:

- `/connect <ссылка>` — подключиться к встрече Телемоста и начать запись
- `/stop` — остановить запись и выйти из встречи
- `/status` — активна ли сейчас сессия записи
- `/help` — список команд

Доступно **всем** (нужно на этапе настройки):

- `/id` — показать `chat_id` этого чата, тему (`thread_id`) и твой `user_id`.
  Используй для `GROUP_CHAT_ID`/`GROUP_THREAD_ID`. Ограничен только чатом (не
  темой), чтобы можно было узнать `thread_id` любой темы.

Если задан `GROUP_CHAT_ID`, бот отвечает **только в этом чате** — в других
группах и в личке он молчит и ничего не обрабатывает. Если задан ещё и
`GROUP_THREAD_ID`, команды из других тем получают короткую подсказку перейти
в нужную тему (со ссылкой на неё).

Свои сообщения (статусы записи, автостоп и **само видео**) бот шлёт в ту же
тему форума, где дали `/connect`, а не в General. Если группа обычная (без тем)
или команду дали в General — пишет как раньше, без темы.

Пока идёт запись, бот сам напоминает в чат: каждые `STATUS_REMINDER_MINUTES`
минут — что всё ещё пишет, и после `LECTURE_DURATION_MINUTES` минут — что
лекция, возможно, уже закончилась.

После остановки бот проверяет файл через `ffprobe`, отправляет его в чат и —
если отправка удалась, — по умолчанию удаляет локальную копию из `recordings/`,
чтобы не забивать диск (управляется `DELETE_AFTER_SEND`). Битые, слишком большие
(>45 МБ) или неотправленные файлы **не удаляются** — их можно забрать с сервера.

## Настройки (`.env`)

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `BOT_TOKEN` | — | Токен бота от @BotFather. **Обязательно.** |
| `GROUP_CHAT_ID` | `0` | ID группы, где работает бот. Вне её (другие группы, личка) бот молчит. `0` = любой чат (для прода не рекомендуется). Узнать: команда `/id`. |
| `GROUP_THREAD_ID` | `0` | ID темы (topic) форума. Если задан — бот работает только в ней, из других тем просит перейти в нужную. `0` = любая тема. Узнать: `/id`. |
| `RECORD_ENABLED` | `true` | `true` — писать видео через ffmpeg (нужен Docker). `false` — только тестировать подключение без записи. |
| `DELETE_AFTER_SEND` | `true` | После успешной отправки видео удалять локальную копию из `recordings/` (экономия места). Удаляется только если файл прошёл проверку `ffprobe` и реально отправился. |
| `LOG_LEVEL` | `DEBUG` | Уровень логов (`DEBUG` — максимум подробностей). |
| `STATUS_REMINDER_MINUTES` | `20` | Как часто напоминать в чат, что бот всё ещё пишет. `0` — выключить. |
| `LECTURE_DURATION_MINUTES` | `90` | Через сколько минут напомнить, что лекция, вероятно, закончилась. `0` — выключить. |
| `VIDEO_SIZE` | `1920x1080` | Разрешение записи (совпадает с Xvfb). |
| `FRAMERATE` | `25` | Кадров в секунду. |
| `DISPLAY` | `:99` | Виртуальный дисплей X11 (задаётся в Docker). |
| `PULSE_SINK` | `MeetingSink` | Имя виртуального аудио-синка PulseAudio. |
| `END_CALL_MARKERS` | набор фраз | Тексты на странице, по которым бот понимает, что звонок завершён. По умолчанию ловит в т.ч. «организатор завершил встречу» и стойкую модалку «оцените качество связи» (она не пропадает как всплывашка). |

> Настройки `HEADLESS` **больше нет** — браузер всегда headed (см. врезку выше).

## Дебаг

- Все действия логируются в консоль (`docker compose logs -f`), уровень — через
  `LOG_LEVEL`.
- При любой проблеме с UI Телемоста бот сохраняет скриншот в
  `debug_screenshots/` с понятным именем (`goto_failed`, `not_logged_in`,
  `join_button_not_found`, `after_join_attempt`, ...) — начни с них.
- Если ffmpeg падает сразу — его вывод попадёт в лог с префиксом `[ffmpeg]`.
- Если в логах есть предупреждение «Нет ни … сессии Яндекса ещё нет» или
  «storage_state.json не найден» — портативная сессия не создана либо не
  примонтирована; выполни `scripts/save_session.py` (см. врезку про «гостя»).

### Что в логах — НЕ баг (можно игнорировать)

Телемост — тяжёлое SPA, поэтому в консоли браузера всегда много «страшных» на
вид строк. Это шум самой страницы, а не ошибки бота. Если запись, звук и
отправка в чат прошли — перечисленное ниже безопасно игнорировать:

- `Refused to connect to 'wss://mc.yandex.ru/...' ... Content Security Policy` —
  это Яндекс.Метрика, её режет собственная CSP-политика Телемоста. К записи
  отношения не имеет.
- `The AudioContext was not allowed to start` — политика автозапуска звука в
  Chromium. Звук встречи пишется через PulseAudio отдельно, это не мешает.
- `Unsatisfied version ^18.0.0 ... shared singleton module react/react-dom` —
  внутреннее предупреждение самого Телемоста о версии React.
- `Can't enable audio - microphone not selected` / `Can't set video status -
  camera not selected` — в Docker нет реальных микрофона/камеры, поэтому они и
  так выключены. Это ровно то, что нам нужно (заходим без звука/видео).
- `Кнопки выключения не найдены (микрофон=False, камера=False)` и
  `Ни один селектор не сработал ... turn-off-mic-button` — следствие того же:
  раз устройств нет, кнопок «выключить микрофон/камеру» на превью тоже нет.
- `Селектор не сработал (...Продолжить в браузере...)` — под залогиненной
  сессией этот экран обычно пропускается, и мы сразу попадаем на превью камеры.
  Ожидаемо.
- `Wake Lock permission request denied` — браузеру не дали «не гасить экран».
  Для записи в Xvfb неважно.
- `[GOLOOM] ... ROOM_HAS_BEEN_CLOSED` / `goloom:error Room has been closed` —
  это и есть событие конца встречи: по нему бот штатно останавливает запись.
  Не ошибка.
- `W: [pulseaudio] ... not intended to be run as root` — безобидное
  предупреждение PulseAudio внутри контейнера.

А вот что стоит воспринимать всерьёз: строки уровня `ERROR` от `bot`/`recorder`,
скриншоты `join_button_not_found` или `not_logged_in`, сообщение «Файл записи
не найден» и вердикт `валиден=False` от `ffprobe`.

## Известные ограничения

Что почти наверняка придётся доделать руками (это же MVP):

1. **Селекторы кнопок** (`CONTINUE_IN_BROWSER_SELECTORS`, `MUTE_*_SELECTORS`,
   `JOIN_BUTTON_SELECTORS` в `browser_worker.py`) сняты с живой вёрстки
   Телемоста и **сломаются, если Яндекс её поменяет**. Открой реальную встречу
   в обычном Chrome, глянь DevTools → Elements и поправь селекторы (см.
   скриншот `join_button_not_found`).
2. **Маркеры конца звонка** (`END_CALL_MARKERS`) — сверь с реальным текстом,
   который Телемост показывает после завершения встречи.
3. **Кроссплатформенная сессия.** Куки в профиле Chromium шифруются ключом ОС и
   не переносятся Windows↔Linux, поэтому сессия хранится ещё и в портативном
   `storage_state.json` — его бот и использует. Если сессия протухнет или Яндекс
   поменяет схему авторизации, пересоздай её через `save_session.py`. См. врезку
   в разделе Docker.
4. **Лимит Telegram на файлы (~50 МБ).** Лекция на час-полтора в него не влезет —
   тогда бот не шлёт файл, а пишет путь к нему в `recordings/`. Для больших
   файлов нужен локальный Bot API сервер (отдельная настройка).
5. **Запись — это захват экрана браузера**, а не «чистый» поток встречи.
   Качество зависит от `VIDEO_SIZE`/`FRAMERATE` и ресурсов машины.
6. **Одна встреча за раз** на весь процесс бота (сознательное упрощение MVP).
